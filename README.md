## Описание проекта

Учебная практика посвящена автоматизации производственных процессов при выпуске медицинских изделий одноразового применения. В качестве конкретного изделия рассматриваются одноразовые шприцы.

Основной бизнес-процесс — «Подготовка и запуск производственной партии одноразовых медицинских шприцев». Цель работы — разработать программное обеспечение для автоматизации отдельных операций этого процесса.

## Планируемая архитектура

В дальнейшем предполагается разработать:

- **Telegram-бот на Java и Spring Boot** — интерфейс для оператора участка;
- **микросервис на Python и FastAPI** — обработка данных и выполнение бизнес-логики.

Взаимодействие компонентов планируется через REST API с использованием JSON. На текущем этапе в репозитории представлены консольные версии программы для КТ2 и КТ3. Telegram-бот и микросервис ещё не реализованы.

## КТ2 — аналитический этап

На этапе КТ2 изучен процесс подготовки и запуска производственной партии. Разработаны BPMN-модель и логическая модель данных.

На BPMN-диаграмме показаны участники процесса, последовательность действий, проверки материалов, документации и оборудования, а также варианты завершения процесса: запуск партии или перенос с указанием причины.

Исходный файл BPMN-модели: `bpmn.bpmn`.

### Программа КТ2

Для демонстрации отдельных операций разработана консольная программа на Python. Она позволяет:

- зарегистрировать производственную партию;
- рассчитать потребность в материалах;
- проверить остатки;
- подобрать доступное оборудование;
- зафиксировать результат контроля, запуск или перенос партии.

Демонстрационные данные находятся в `src/demo_data.json`. Для запуска требуется Python 3.10 или новее. Дополнительные библиотеки не нужны.

Запуск из корня репозитория:

```bash
python src/main.py
```

По умолчанию выполняется сценарий `ready`. Для проверки других ситуаций можно указать параметр `--scenario`:

| Сценарий | Результат |
|---|---|
| `ready` | Партия готова к запуску |
| `shortage` | Недостаточно материалов |
| `busy` | Требуемое оборудование недоступно |
| `quality_rejected` | При проверке выявлено несоответствие |

Пример запуска:

```bash
python src/main.py --scenario busy
```

Подробнее о Python-версии: [src/README.md](src/README.md).

## КТ3 — объектно-ориентированная реализация

На этапе КТ3 программа переработана с использованием объектно-ориентированного подхода на Java. Для сущностей логической модели созданы отдельные классы. Операции подготовки и запуска партии перенесены в сервисный класс.

В программе используются:

- **инкапсуляция** — данные сущностей хранятся в закрытых полях, доступ к ним осуществляется через методы;
- **наследование и интерфейс** — проверки готовности реализованы через общий интерфейс и классы правил;
- **полиморфизм** — правила материалов и оборудования используются через общий тип;
- **коллекции** — данные и результаты операций хранятся в списках.

Классы распределены по пакетам:

| Пакет | Назначение |
|---|---|
| `medical` | Запуск демонстрационной программы |
| `medical.model` | Классы сущностей |
| `medical.service` | Операции над данными и результаты проверок |
| `medical.rules` | Правила готовности партии к запуску |

Java-версия использует те же демонстрационные данные и сценарии, что и Python-версия. Для хранения данных применяются JSON-файлы и коллекции в памяти; подключение к СУБД не требуется.

### Диаграмма классов

Для отображения структуры ООП-реализации подготовлена UML-диаграмма классов. На ней представлены классы, их атрибуты и методы, а также связи между ними.

Исходный файл диаграммы: `classes.drawio`.

### Проверка программы

Работа программы проверялась на четырёх сценариях: `ready`, `shortage`, `busy` и `quality_rejected`. Результаты Java- и Python-версий сравнивались между собой.

Также проверены отдельные операции сервиса, в том числе проверка материалов, назначение оборудования и обработка результатов контроля.

Инструкция по сборке, запуску и проверке Java-версии находится в [src/java/README.md](src/java/README.md).

## Взаимное рецензирование

На этапе КТ3 проведено взаимное рецензирование проектов с одногруппником. В ходе проверки рассмотрены структура программы, использование принципов ООП, соответствие диаграммы коду и работа основных сценариев.

По замечаниям рецензента уточнено сравнение дат протоколов контроля: при совпадении времени учитывается идентификатор протокола. Также выполнено разделение Java-классов по пакетам.
